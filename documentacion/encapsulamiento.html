Encapsulamiento en Taller ICNO
Proyecto Final de Programación Orientada a Objetos · Autor: Isaac Navarro · Todo el código de las clases está en inc/taller.php
Qué es. Encapsular es guardar los datos de un objeto bajo llave: los atributos se declaran private y solo se leen con un getter (getCostoBase()) o se cambian con un setter (setCostoBase()). Si una página intenta $servicio->costoBase = -5;, PHP lo rechaza. Así el objeto siempre controla su propio estado y, si hay que validar un dato, se hace en un solo lugar.

1Las tres reglas que cumplen las 11 clases

ReglaEn el código
a) Atributos privateLas 11 clases declaran private $x;. No existe ningún atributo public.
b) Acceso por getters y settersCada atributo tiene su getX(); los que pueden cambiar tienen también setX().
c) $this dentro de la claseConstructores, getters y setters escriben $this->x: "el dato de este objeto".

5Decisiones de diseño: no todo tiene setter

  • Usuario no tiene setters: nadie puede "ascenderse" con $u->setRol('admin'). El rol solo lo pone la base de datos.
  • Cotizacion es un comprobante: total y servicios no se editan. Para marcarla revisada se usa Taller->marcarRevisada().
  • Taller guarda la conexión $bd privada y sin getter: ninguna página puede escribir SQL por su cuenta.
  • Los métodos *DesdeFila() son private: convertir una fila SQL en objeto es asunto interno de Taller.

2Ejemplo real: clase Servicio (líneas 28 a 54)

class Servicio {
    private $id;  private $descripcion;  private $costoBase;   // Bajo llave.
    public function __construct($id, $descripcion, $costoBase) {
        $this->id = $id;                        // $this = este objeto.
        $this->descripcion = $descripcion;
        $this->costoBase = $costoBase;
    }
    public function getCostoBase() { return $this->costoBase; }    // Getter
    public function setCostoBase($c) { $this->costoBase = $c; }      // Setter
    // ... igual para id y descripcion (getId/setId, getDescripcion/setDescripcion)
}

4Las hijas también respetan lo privado del padre

Como $costoBase es privado en Servicio, ni sus hijas lo ven directo. ServicioPreventivo calcula con el getter del padre, y en su constructor lo del padre lo guarda el padre con parent::__construct():

#[\Override] public function calcularCosto() { return $this->getCostoBase() * 0.9; }  // linea 66

8Encapsulamiento a nivel de sistema

  • Contraseñas: password_hash() y password_verify(). Usuario ni siquiera tiene atributo de contraseña.
  • Credenciales: en inc/config.php, fuera del repositorio y bloqueado por Apache (403).
  • Sesión: solo guarda el id; exigirRol() pregunta al objeto con esAdmin().
  • Salida HTML: todo texto del usuario pasa por htmlspecialchars().

Resumen para la revisión: todos los atributos son privados y se usan con getters y setters que escriben $this; los setters se omiten a propósito donde el dato no debe cambiar (Usuario, Cotizacion); la conexión a la base de datos vive privada y sin getter dentro de Taller, que es la única clase que escribe SQL. El resto del sistema trabaja solo con objetos y sus métodos públicos.
