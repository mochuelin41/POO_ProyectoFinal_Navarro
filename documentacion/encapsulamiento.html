Encapsulamiento en Taller ICNO
Proyecto Final de Programación Orientada a Objetos · Isaac Navarro · Código en inc/taller.php

1. Qué es el encapsulamiento y por qué lo usamos

Encapsular es guardar los datos de un objeto bajo llave y dejar que solo se lean o cambien por métodos que la propia clase ofrece. Los atributos se declaran private, así que ninguna página del sistema puede hacer $servicio->costoBase = -5;: PHP lo rechaza con un error. Para leer se usa un getter (getCostoBase()) y para cambiar un setter (setCostoBase()). La ventaja es que el objeto siempre controla su propio estado: si mañana hay que validar un dato, se hace en un solo lugar y todo el sistema queda protegido.

2. Cómo está aplicado: las tres reglas que cumplen las once clases

ReglaCómo se ve en el código
a) Todos los atributos son privateLas 11 clases declaran sus atributos con private $nombre;. No hay ningún atributo public en el proyecto.
b) Acceso solo por getters y settersCada atributo que se necesita afuera tiene su getX(); los que pueden cambiar tienen además su setX().
c) Se usa $this dentro de la claseConstructores, getters y setters escriben $this->atributo, es decir, "el dato de este objeto", no de otro.

Ejemplo completo: la clase Servicio (líneas 28 a 54)

class Servicio {
    private $id;            // Nadie fuera de la clase puede tocarlo directo.
    private $descripcion;
    private $costoBase;

    public function __construct($id, $descripcion, $costoBase) {
        $this->id = $id;                     // $this = "este objeto en particular".
        $this->descripcion = $descripcion;
        $this->costoBase = $costoBase;
    }
    public function getCostoBase() { return $this->costoBase; }              // Getter: lectura controlada.
    public function setCostoBase($costoBase) { $this->costoBase = $costoBase; } // Setter: cambio controlado.
    public function getDescripcion() { return $this->descripcion; }
    public function setDescripcion($d) { $this->descripcion = $d; }
    public function getId() { return $this->id; }
    public function setId($id) { $this->id = $id; }
}

Las hijas también respetan lo privado del padre

Como $costoBase es private en Servicio, ni siquiera sus hijas lo ven directo. Por eso ServicioPreventivo calcula su costo con el getter del padre y no con el atributo:

#[\Override] public function calcularCosto() { return $this->getCostoBase() * 0.9; }   // linea 66

Y en el constructor de la hija, lo del padre lo guarda el padre con parent::__construct(); la hija solo guarda lo suyo ($this->kilometraje). Cada clase es dueña únicamente de sus propios datos.

3. Decisiones de diseño: no todo tiene setter a propósito

El encapsulamiento no es solo poner private y luego regalar un setter para todo. También es decidir qué se puede cambiar y qué no:

  • Usuario tiene getters pero ningún setter. Un usuario no cambia de id, correo ni rol desde las páginas; eso solo lo hace la base de datos. Así nadie puede "ascenderse" a admin escribiendo $u->setRol('admin').
  • Cotizacion tampoco tiene setters. Una vez calculada es un comprobante: su total y sus servicios no se editan. Para marcarla como revisada se usa Taller->marcarRevisada(), que actualiza la base de datos.
  • Taller guarda la conexión $bd privada y sin getter. Ninguna página puede obtener la conexión ni escribir SQL por su cuenta. Es la forma más fuerte de encapsular: el dato existe, pero solo la clase lo usa.
  • Los métodos usuarioDesdeFila(), vehiculoDesdeFila(), servicioDesdeFila() y cotizacionDesdeFila() son private. Convertir una fila SQL en objeto es un detalle interno de Taller; las páginas solo reciben objetos ya armados.

4. Cómo trabajan las páginas con los objetos

Las páginas PHP (servicios.php, cotizar.php, mis_cotizaciones.php, etc.) nunca ven atributos ni tablas. Solo llaman métodos públicos. Ejemplos reales:

5. Encapsulamiento a nivel de sistema

  • Contraseñas: se guardan con password_hash() y se comparan con password_verify(). La clase Usuario ni siquiera tiene un atributo de contraseña: el dato más sensible no sale nunca de la base.
  • Credenciales de la base: viven en inc/config.php, archivo fuera del repositorio (.gitignore) y bloqueado por Apache (HTTP 403). El código público no contiene secretos.
  • Sesión: solo se guarda el id del usuario; cada página reconstruye el objeto con usuarioActual() y exigirRol() decide si puede entrar. La página no decide, el objeto Usuario responde con esAdmin().
  • Salida HTML: todo texto que viene del usuario pasa por htmlspecialchars() al mostrarse.
